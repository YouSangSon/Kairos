# Core architecture gates

The dependency gate recursively checks every production Go package and builds both package and module import graphs. Cross-owner imports target `contracts`. Private implementations remain under each owner's nested `internal` directory. The only shared calculation package is `internal/exact`.

SQL ownership uses the production `storage/ownership` registry and its finite SQL parser. SQL belongs in an owner's private SQLite adapter. Literal and constant expressions are resolved; variables, escaped SQL method values, unresolved expressions, CTEs, unknown scalar functions, numbered parameters, named parameters, and unbounded table-valued functions are rejected. The fixed schema `pragma_*` functions require an owned object literal. The existing row-local `json_each(NEW.column)` form preserves the same FROM-list ownership checks. Supported SELECT subqueries and joins inspect every referenced table. Catalog Boolean predicates must restrict every OR branch to owned schema objects. Registered catalog parameters must cover every object argument position returned by that same parser. Runtime authorization remains responsible for exact statement and bound-argument enforcement.

`legacy_symbols.json` records the baseline legacy root and legacy internal paths, declaration names and AST hashes from `25f077a`. These temporary exemptions preserve the original implementation during atomic migration. Deleting migrated files, whole declarations, or individual imports is allowed. Grouped constants and types remain one frozen declaration unit. Changing retained symbols or introducing legacy paths or symbols fails the gate. New module code has no hash exemption. Remove obsolete baseline entries after the corresponding migration is integrated; do not regenerate the baseline to admit behavior changes.

`migration_history.json` freezes only the existing 001–027 migration bytes for this refactor. Later migrations still pass owner registry and schema inventory checks. Historical hashes do not replace schema, transaction, restore or behavior tests.

`ValidateSchema` reads the actual migration sources, verifies declared table and schema object ownership, and inspects trigger bodies with the shared SQL parser. This CREATE inventory does not authorize ALTER or other migration operations. The canonical registry contains 32 business tables and the maintenance-owned `schema_migrations` control table. This source inspection does not prove the contents of a running database or replace maintenance migration and proof tests.

`internal/codec` and the outer Kiwoom SDK are new infrastructure, not legacy exemptions. Codec helpers remain pure and are imported only by adapters or construction code. SQL source checks also cover these infrastructure paths. The mock SDK constructor and submit method have one sealed trading adapter; its module Compose is the adapter factory caller. Migration construction is maintenance-only. The observation migration verifier has one fixed `SELECT 1` lifetime probe exception. Private SQL forwarding methods are accepted only when one return directly preserves the receiver, context, query and argument list.

The Go research compatibility module owns only artifact queries and bounded file reads. It has no SQL or observation storage authority and cannot import trading. Owner HTTP and CLI adapters keep inbound transport code private. Root `RegisterHTTP`, `ComposeHTTP`, and `RunCLI` are fixed construction or delegation entrypoints; other modules consume contracts and composition calls module roots. Only `ComposeHTTP` may return `http.Handler`. The shared `transport/httpjson` helper stays outside business layers and cannot import modules or own SQL.
